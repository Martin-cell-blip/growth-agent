# REQ-001 · v0.1 人工基线漏斗（无 Agent）
> 状态：草稿待裁决 · 对应工期 W1-W2
> 原则：**先有业务，再谈 AI 提效**。v0.2 起所有 Agent 增益都以本版数字为分母。

## 1. 为什么第一个迭代不写 Agent
- 没有基线就没有"提升"——无修改可用率、提效倍数都需要人工版分母
- Check 清单、指标口径、product-truth 文件在本版先以"人工规则"沉淀，v0.2 才有东西可自动化
- 这本身是要写进面试的产品判断：**AI 项目的第一个迭代应该没有 AI**

## 2. 需求清单（AC = 验收标准，EV = 验证用例，一一对应）

**R1 漏斗口径定义** → 交付 `funnel_spec.md`
- AC-01 visitor / lead / activated 三态判定边界成文、无歧义 ｜ EV-01 冷读测试：一名未参与写作的读者（可为 AI 冷读）独立复述，与原意一致
- AC-02 六事件定义齐全：visit / scroll50 / email_submit / email_confirm / first_generation / d7_return ｜ EV-02 每事件有触发条件与去重规则

**R2 英文落地页（两版首屏 A/B）**
- AC-03 两版价值主张（省备课时间 vs 对齐考纲）经 URL 参数分流 ｜ EV-03 实测两变体可达且埋点可区分
- AC-04 页面所有产品声称 100% 溯源到 `product-truth.md` ｜ EV-04 逐句对照，0 条无源声称

**R3 埋点（Plausible）**
- AC-05 六事件全部上报、后台可查 ｜ EV-05 逐事件触发实测清单
- AC-06 UTM 规范成文、渠道可区分 ｜ EV-06 两个不同 UTM 实测入库

**R4 留资链路（双重确认）**
- AC-07 提交 → 确认邮件 → confirmed 全流程通 ｜ EV-07 真实邮箱走通并留档
- AC-08 退订链接生效 ｜ EV-08 实测退订——合规检查是 Check 层的前身

**R5 邮件序列骨架（人工版，D0/D2/D5/D9/D14）**
- AC-09 5 封英文邮件定稿，每封过人工版 Check 清单（术语 / 声称溯源 / 单一 CTA / 长度 / 垃圾词 / locale 拼写）｜ EV-09 逐封勾检查单
- AC-10 每封按 `specs/baseline_protocol.md` 执行并记录产出耗时（分段：起草/修改/核对；每封全新会话，禁提示词沉淀） ｜ EV-10 计时表——**v0.2"提效"声称的分母在这里**，违例封剔除或单列

**R6 周报模板（人工版）**
- AC-11 模板含漏斗数字 / 实验状态 / 异常 / 下周计划四节 ｜ EV-11 第一份周报产出——这是 v0.4 funnel-analysis skill 的规格原型

**R7 托管 Demo（无 key 模式）〔2026-08-28 增补，已裁决通过；质量前提当日已实测〕**
- AC-12 Demo 公网可达，运行于无 key 模式（确定性预检 + 回退 coach）；页面明示完整 AI criterion 反馈不在 Demo 内 ｜ EV-12 无痕浏览器实测可达
- AC-13 `first_analysis` 事件上报 ｜ EV-13 部署后实测入库
- AC-14 一键加载**弱样例草稿**，且该样例触发 8/8 预检信号 + ≥8 条 coach findings ｜ EV-14 部署后重测（2026-08-28 本地已验证：79 词弱稿 → 8/8 非 pass + 11 条 findings）
- AC-15 双样例对照：弱稿（11 findings）与好稿（7/8 pass）均可一键加载——before/after 对照即产品叙事 ｜ EV-15 两样例实测
- 已知弱点如实入档：claim 阶段问题库对同类 claim 重复同一问题（弱稿实测 4 条重复"​What evidence would justify this claim"）；Demo 不掩饰，列为 v0.2 skill 优化候选
